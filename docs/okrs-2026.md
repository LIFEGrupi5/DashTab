# DashTab — OKRs Q3 2026 (Jul–Sep)

> **Rubric:** M6.5 — AI-assisted OKRs  
> **Drafted with:** Claude Sonnet 4.6 (Claude Code), initial draft generated from the product context prompt below, then reviewed and adjusted by the team.  
> **AI prompt used:** *"You are the PM for DashTab — a multi-tenant restaurant OS covering POS, KDS, payments, analytics, and AI-powered menu recommendations. We have PostHog analytics live (NSM, conversion funnel, A/B test), Stripe subscriptions, Uptime Kuma (99.9% SLA target), and a customer-facing AI recommendation page. Draft 3 OKRs for Q3 2026 with 3–4 measurable Key Results each. KRs must reference metrics we can actually observe today."*

---

## Objective 1 — Grow the paying restaurant base

**Why:** The product is live and has its first pilot tenants. Q3 is the first full quarter with a working Stripe checkout + onboarding flow. The North Star Metric (active staff using the KDS/orders module) is meaningful only once there are paying restaurants to measure.

| # | Key Result | Baseline (Jun 2026) | Target (Sep 2026) | How we measure |
|---|---|---|---|---|
| KR1.1 | Trial → paid conversion rate | ~0% (no trials yet) | ≥ 15% | Stripe dashboard: `trialing → active` subscriptions |
| KR1.2 | Paying restaurants onboarded | 0 | ≥ 5 | Stripe `active` subscription count |
| KR1.3 | Pricing page CTA click-through rate (A/B test M6.4) | baseline variant | ≥ +20% vs control | PostHog `pricing_cta_clicked` funnel, variant vs control |
| KR1.4 | Time-to-first-order after registration | unknown | ≤ 48h | PostHog: gap between `restaurant_registered` and first `order_placed` |

*Team review note: Jeta flagged KR1.3 needs the A/B test to run for at least 3,206 visitors/variant before calling a winner (from the M6.4 sample-size calculation). Adjusted the target to reflect a directional signal, not a final decision.*

## Objective 2 — Deliver a fast, reliable product that restaurants trust

**Why:** A restaurant SaaS lives or dies on reliability during dinner service. Uptime Kuma (DO-7) and Prometheus (DO-5) are live — Q3 is the first quarter where we can hold ourselves to an SLA.

| # | Key Result | Baseline (Jun 2026) | Target (Sep 2026) | How we measure |
|---|---|---|---|---|
| KR2.1 | Backend uptime (Uptime Kuma, 30-day rolling) | ~99.5% | ≥ 99.9% | Uptime Kuma public status page |
| KR2.2 | p95 KDS order-status update latency (SignalR round-trip) | ~300ms (after Redis backplane fix) | < 200ms | Prometheus `signalr_hub_method_duration_p95` |
| KR2.3 | Mean time to detect (MTTD) for production incidents | 47 min (postmortem baseline) | < 10 min | Time from incident start to AIOps/Grafana alert firing |
| KR2.4 | Zero P1 incidents (full service outage > 10 min) | n/a | 0 | Uptime Kuma 10-min downtime window + incident log |

*Team review note: Enes flagged KR2.2 requires the Redis backplane to be stable (fixed in the Jun 14 patch) — otherwise latency measurements are noise. Agreed to start the measurement clock from Jul 1.*

## Objective 3 — Make AI a visible, measurable part of the product

**Why:** The AI recommendation feature (Phase 1B RAG) and Unleash feature flag are live. Q3 is the first quarter we can measure real AI engagement. The rubric also requires demonstrating AI-product thinking, not just AI-infra.

| # | Key Result | Baseline (Jun 2026) | Target (Sep 2026) | How we measure |
|---|---|---|---|---|
| KR3.1 | AI recommendation requests per week (post flag-on) | 0 (flag gated) | ≥ 200/week | `recommendation_ai_blurb_generated_total` Prometheus counter |
| KR3.2 | AI recommendation fallback rate | 100% (flag off) | < 10% once enabled | `recommendation_fallback_total / (generated + fallback)` |
| KR3.3 | Customer feedback sentiment score (M6.6 baseline) | n/a (first measurement) | ≥ 70% positive reviews | Script re-run on real feedback if captured; PostHog survey event |
| KR3.4 | Embedding coverage across all restaurant menus | 0% | ≥ 95% (all active items embedded) | `SELECT count(*) WHERE embedding IS NULL` vs total active items |

*Team review note: Olti flagged KR3.1 depends on the Unleash `menu-recommendations` flag being enabled for pilot restaurants — set a flag-on date of Jul 7 to give one week of setup. KR3.2 is only meaningful once the flag is on; the 10% target accounts for occasional OpenAI outages handled by graceful degradation.*
